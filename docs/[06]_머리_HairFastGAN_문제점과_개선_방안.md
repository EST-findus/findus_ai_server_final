# [06] 머리(HairFastGAN) 문제점과 개선 방안

`POST /v1/hair` 의 머리 스타일 바꾸기(HairFastGAN)에 지금 남아 있는 문제와, 고칠 방법을 정리한다.
2026-10-27 기준으로 이 저장소 코드(`src/hairstyle.py`, `src/hair_fit.py`, `app/engine.py`)와 문서(docs/[00], [01]), ai_lab 문서([04], [20], [21], [22])를 다시 읽고 정리했다. 이 문서를 쓰면서 새로 돌려 본 것은 없다. 숫자는 모두 각 문서에서 이미 잰 값이고 출처를 붙였다.

## 0. 요약

| 번호 | 문제 | 심각도 | 개선 방안 (우선순위 순) |
|---|---|---|---|
| 1 | 원래 앞머리 자리에 이마 자국이 남음 | 높음 (눈에 바로 보임) | 화면 안내 → 이마 자국 감지 → Stable-Hair 머리 지우기 시험 |
| 2 | 느림 (1장 약 1분), 6GB 를 넘침 | 높음 (나이 3개면 2~3분) | 처리할 장 수 줄이기 → fp16·모듈별 올리기 → 기다리는 시간 안내 |
| 3 | 결과 확인이 사진 1~2장뿐 | 높음 (일반화 모름) | Validation 4명 × 스타일 8종 눈 검사 |
| 4 | 참조 자동 고르기가 쉽게 뒤바뀜 | 중간 | 얼굴 폭이 비슷하면 품질 점수로 고르기 |
| 5 | 스타일별 참조가 3장뿐, 트렌드 스타일 사진 없음 | 중간 | AI Hub Training 에서 5장까지 늘리기 |
| 6 | 머리를 바꾸면 ArcFace 가 떨어짐 | 낮음 (원칙상 채점 안 함) | 지금처럼 참고만. 응답에 경고 표시 검토 |
| 7 | 보완 처리의 작은 흠 (눈썹, 피부결) | 낮음 | 4명 검사에서 함께 확인 |
| 8 | 시험 페이지에서 스타일 바꾸기를 눌러 보지 않음 | 낮음 | 브라우저로 한 번 끝까지 눌러 보기 |

## 1. 지금 구조 (한 장을 바꿀 때)

```
입력 얼굴 (FFHQ 정렬 1024)
 ├─ ① 원래 머리 지우기 remove_hair       ← 이마는 주변 피부색 + 볼 피부결, 나머지는 배경색
 ├─ ② 참조 고르기 HairPost._plan          ← 스타일당 3장 중 얼굴 폭이 가장 비슷한 것 (품질 규칙에 걸리면 건너뜀)
 ├─ ③ 참조 배경·옷 지우기 clean_ref       ← 어두운 배경을 머리로 읽지 않게
 ├─ ④ HairFastGAN (GPU, 약 5.5GB)
 ├─ ⑤ 얼굴 지키기 composite_face          ← 눈·코·입·피부는 입력 그대로
 ├─ ⑥ 이마 밝기 맞추기 tone_forehead, 눈썹 채우기 mirror_brow
 └─ ⑦ 머리 색 칠하기 (Lab, src/hair_color.py)
```

①·③·⑥ 은 ai_lab 에서 2026-10-19 에 일그러짐과 잔머리를 고치려고 넣은 것이다 (ai_lab docs/[21], [22]). 이 서버는 그 코드를 그대로 가져왔다.

## 2. 문제점

### 2-1. 원래 앞머리 자리의 이마 자국

- **증상**: 입력에 앞머리가 있는데 이마가 드러나는 스타일(짧은 머리 등)을 고르면, 원래 앞머리 끝이 이마 가운데에 세모 자국으로 남는다. 서버를 만든 날 kid.jpg(짧은 머리 + 애쉬 브라운)에서 봤고, ai_lab 코드로 돌려도 똑같이 나왔다 (docs/[01] 2026-10-20).
- **원인**: 앞머리에 가려졌던 곳에는 진짜 이마 정보가 없다. ①에서 주변 피부색으로 칠해도, HairFast 가 칠한 자리를 다시 그리면서 흔적을 남긴다. ⑤ 얼굴 지키기는 '입력에서 얼굴이던 곳'만 되돌리므로 이 자리를 고치지 못한다.
- **이미 해 본 것** (ai_lab docs/[20] 1-3, [22] 3장):

| 방법 | 결과 |
|---|---|
| 결과 이마를 평균 피부색 + 잡음으로 덮기 | 붙인 티가 남음 |
| LaMa 인페인팅 | 주변이 머리라 이마에 머리를 이어 그림 |
| 주변 피부색 퍼뜨리기 | 붉게 뜨고 눈썹 위 물결 자국 |
| ①~④ (머리 지우기·띠 제외·이마 밝기·눈썹 채우기) | 시험한 아이 사진에서는 깨끗해졌지만, kid.jpg 에는 세모 자국이 남음 |

- **결론**: 영상처리로는 한계가 있다. 빈 이마를 새로 그려 줄 생성 모델이 필요하다.

### 2-2. 속도와 GPU 메모리

| 항목 | 값 | 출처 |
|---|---|---|
| 모델 올리기 | 17.5초, VRAM 5.5GB | ai_lab docs/[04] 3장 (2026-10-15) |
| 변환 중 최대 VRAM | 7.8~8.6GB (6GB 를 넘어 공유 메모리로 넘침) | ai_lab docs/[04] 3장 |
| 서버 요청 1장 (처음 올림 포함) | 58.2초, 81.8초 | docs/[00] 6장 (2026-10-20) |
| 서버 요청 1장 (이 PC) | 42.1초 | docs/[01] 2026-10-20 |

- 논문의 "V100 에서 1초 미만"보다 수십 배 느리다. GPU 메모리가 모자라 공유 메모리를 쓰기 때문이다.
- `result_id` 로 나이 3개에 다 입히면 2~3분이 걸린다 (docs/[00] 6장).
- GPU 는 한 번에 한 요청만 쓰고, 기다리는 요청은 300초(`QUEUE_TIMEOUT`)가 지나면 503 을 받는다. 앞 요청이 머리 3장이면 뒤 요청은 503 을 받기 쉽다. (코드로 본 추정이다. 실제로 겪거나 재 보지는 않았다.)
- 나이 변환을 하면 HairFast 를 내리므로, 나이 → 머리 → 나이 → 머리를 오가면 그때마다 다시 올리는 약 17초가 붙는다.

### 2-3. 확인한 사진이 너무 적다

- 서버에서 확인한 것은 kid.jpg 한 장과 `data/hair_refs/M/short/` 사진 한 장이다 (docs/[01]).
- ai_lab 에서도 품질 규칙 기준값은 **덮머 8장**만 입혀 보고 정했고, 잔머리 보완은 **아이 사진 1장**으로만 확인했다 (ai_lab docs/[21] 2-2, [22] 5장).
- 여자 스타일 5종, 긴 머리, 앞머리가 없는 얼굴, 성인 얼굴에서 ①(머리 지우기)이 오히려 손해를 보는지는 모른다.

### 2-4. 참조 자동 고르기가 쉽게 뒤바뀜

- 자동 고르기는 대상과 참조의 얼굴 폭 비만 본다 (`hair_fit.pick`). 품질 점수는 탈락 여부에만 쓴다.
- 얼굴 폭 비가 거의 같으면(0.97~1.01) 같은 사진을 다시 정렬한 정도의 작은 차이로도 다른 참조가 골라진다. 그래서 같은 사진을 두 번 넣어도 결과가 다를 수 있다 (ai_lab docs/[20] 1-2).
- 사용자가 "아까와 다르다"고 느낄 수 있고, 저장한 결과를 다시 만들 수 없다.

### 2-5. 참조 사진이 적다

- 스타일마다 품질 규칙을 통과한 3장만 쓴다. 남 3종 × 3장 + 여 5종 × 3장 = 24장 (`configs/hair_presets.yaml` `selected_refs`).
- 이 3장이 모두 대상 얼굴과 안 맞으면 고를 것이 없다.
- 트렌드 스타일 13종(댄디컷, 허쉬컷 등)은 한국인 정면 참조 사진이 없어 목록에만 있고 화면에는 나오지 않는다.
- 참조는 AI Hub 사진이라 재배포가 금지돼 있다. 실제 서비스에 쓰려면 이용 조건을 다시 확인해야 한다 (docs/[00] 7장).

### 2-6. 신원 점수가 떨어짐

- 얼굴 지키기를 켜도 이마·눈썹을 새로 만들기 때문에 ArcFace 가 떨어진다. ai_lab 아이 사진에서 잔머리 보완 전후로 0.07~0.11 떨어졌다 (0.833 → 0.722 등, ai_lab docs/[22] 4장).
- 원칙상 머리 결과로는 신원 점수를 매기지 않고(ai_lab docs/[04] 1장), 서버도 머리 단계는 채점하지 않는다. 그래서 점수로는 자동으로 거를 수 없고, 사람이 눈으로 봐야 한다.

### 2-7. 보완 처리의 작은 흠 (ai_lab docs/[22] 5장)

- 옮겨 그린 눈썹은 반대쪽 눈썹이 옅으면 같이 옅다. 양쪽 눈썹이 다 가려졌으면 채우지 못한다.
- 칠한 이마의 피부결은 볼 조각을 뒤집어 깐 것이라, 확대하면 반복 무늬가 보일 수 있다.
- 덮머에서도 앞머리 아래 한쪽이 살짝 밝게 남은 경우가 있었다.

### 2-8. 화면에서 끝까지 눌러 보지 않음

- 시험 페이지 `/test/post` 에서 브라우저로 눌러 본 것은 색만 바꾸기(0.5초)뿐이다. 스타일까지 바꾸는 HairFastGAN 은 화면에서 돌려 보지 않았다 (docs/[01] 2026-10-20).

## 3. 개선 방안

### 3-1. 바로 할 수 있는 것 (새 모델 없음)

| 순서 | 무엇 | 대상 문제 | 방법 | 완료 기준 |
|---|---|---|---|---|
| A | 앞머리 안내 | 2-1 | 입력에 앞머리가 있고(BiSeNet 머리가 눈썹 근처까지 내려옴) 이마가 드러나는 스타일을 고르면, 응답 `info` 와 시험 페이지에 "이마 자국이 남을 수 있음, 앞머리 스타일 권장"을 띄운다 | 안내가 kid.jpg + 짧은 머리에서 뜨고, 앞머리 없는 얼굴에서는 안 뜸 |
| B | 이마 자국 감지 | 2-1, 2-6 | 결과의 '원래 머리였다가 피부가 된 이마'(`tone_forehead` 의 R 영역) 안에서 주변 피부보다 많이 어두운 픽셀 비율을 재서 `info.forehead_mark` 로 돌려준다 | kid.jpg 세모 자국에서 값이 높고, 깨끗한 결과에서 낮음 |
| C | 고르기 안정화 | 2-4 | 얼굴 폭 비 차이가 0.03 안쪽인 참조끼리는 품질 점수(`quality_score`)가 높은 쪽을 고른다 | 같은 사진을 두 번 넣으면 같은 참조 |
| D | 처리 장 수 줄이기 | 2-2 | `result_id` 에 `keys` 를 안 주면 전부 하지 말고 대표 1장만(또는 화면에서 고른 것만) 하도록 시험 페이지 기본값 변경 | 나이 3개 결과에 머리 1장, 약 1분 |
| E | 화면 끝까지 눌러 보기 | 2-8 | 헤드리스 Chrome 으로 `/test/post` 에서 스타일 + 색 적용 | 결과 이미지가 뜨고 걸린 시간 기록 |

### 3-2. 검증 (모든 개선의 기준)

| 순서 | 무엇 | 방법 | 완료 기준 |
|---|---|---|---|
| F | 4명 × 8 스타일 눈 검사 | Validation 4명(얼굴이 좁고 넓은 남녀, 앞머리 있고 없음 섞기) × 성별 스타일 전부 × 자동 고르기. 결과를 한 장 격자로 모아 일그러짐·이마 자국·잔머리·눈썹을 표로 적는다 | 문제별 장 수가 나온 표 (지금 상태의 기준선) |
| G | 처리 시간 재기 | F 를 돌리면서 1장 시간, 처음 올림 시간, 최대 VRAM 을 기록 | docs/[00] 6장 표 갱신 |

F 결과가 나와야 2-1·2-3·2-7 이 실제로 얼마나 자주 나오는지 알 수 있다. 3-3 의 큰 작업은 F 결과를 본 뒤에 할지 정한다.

### 3-3. 시간이 드는 것

| 순서 | 무엇 | 대상 문제 | 방법 | 주의 |
|---|---|---|---|---|
| H | 참조 늘리기 | 2-5 | ai_lab `scripts/hair_length_refs.py` 로 AI Hub Training 에서 후보를 더 뽑고 `scripts/hair_ref_quality.py` 규칙으로 걸러 스타일마다 5장 | 재배포 금지 사진이라 `data/` 에만 두고 커밋하지 않음 |
| I | fp16·모듈별 올리기 | 2-2 | HairFast 안의 인코더·Blending·PostProcess 를 차례로 올렸다 내리거나 fp16 으로 돌려 6GB 안에 맞춘다 | 결과가 바뀌면 전후 비교를 docs/[01] 에 기록 (AGENTS.md 2장) |
| J | Stable-Hair 머리 지우기 | 2-1 | Stable-Hair(SD 1.5, Apache-2.0)의 '대머리 만들기' 단계만 떼어 ① 대신 쓰고, 결과를 HairFast 에 넣는다 | 6GB 에 HairFast 와 같이 안 올라감 → engine.gpu() 차례에 따라 번갈아 올리기. 1장 시간이 더 늘어남 |
| K | StyleGAN 재구성 이마 | 2-1 | 얼굴 지키기 합성을 넓혀, 원래 앞머리 자리 이마는 HairFast 결과 대신 SAM/e4e 재구성 이마를 쓴다 | 재구성 이마가 본인과 비슷한지 F 와 같은 방식으로 확인 |
| L | 트렌드 스타일 참조 | 2-5 | 한국인 정면 사진 + 스타일 라벨이 있는 공개 데이터는 아직 못 찾음 (ai_lab docs/[04] "한국인 머리 참조 사진"). 팀이 직접 찍은 사진이나 이용 허락을 받은 사진을 모으는 쪽 | 초상권·이용 동의 |

다른 머리 모델 조사(HairCLIPv2, HairFusion 등)는 ai_lab docs/[04] 3장에 있다. 6GB 에서는 HairFastGAN 이 여전히 가장 현실적이므로 모델을 바꾸기보다 위 방법으로 보완한다.

## 4. 진행 순서 제안

1. **E** (화면 확인) → **F·G** (4명 검사로 기준선 만들기)
2. **A·C** (안내, 고르기 안정화): 작고 바로 효과가 있음
3. F 에서 이마 자국이 자주 나오면 **B** → **J** 또는 **K** 시험
4. 느린 것이 문제면 **D** → **I**
5. 참조가 모자란 스타일이 보이면 **H**

각 단계가 끝나면 docs/[01] 변경 기록에 잰 값을 적고, 이 문서 0장 표의 상태를 고친다.
