# [07] 얼굴 유사도 측정 원리와 사람 체감과의 괴리

> "눈으로 보면 같은 사람인데 ArcFace 는 왜 0.4 밖에 안 나오나?" 에 답하는 문서다.
> 이미지 유사도를 재는 방법들, ArcFace·AdaFace 가 숫자를 만드는 원리, 사람 체감과 어긋나는 이유, 같이 쓸 수 있는 다른 지표를 정리한다.
> 숫자는 이 저장소 docs/[00]·[01] 에 잰 값과 ai_lab docs/[10] 의 dev/test 값만 쓴다. 새로 돌리거나 잰 것은 없다.

---

## 0. 요약

| 질문 | 답 |
|---|---|
| ArcFace 0.4 는 "40% 닮음" 인가? | **아니다.** 코사인 유사도는 백분율이 아니다. 실제 사진끼리 **남남은 평균 0.046**, 나이가 다른 **본인끼리는 평균 0.443** 이다 (ai_lab docs/[10] 2-D). 0.4 는 "본인 쪽" 점수다 |
| "같은 사람" 기준선은? | 남을 본인으로 잘못 볼 확률 1% 기준 임계값이 **0.278** (ArcFace, ai_lab docs/[10] 2-D) |
| 왜 사람 체감보다 낮게 나오나? | 모델은 **112×112 로 잘라낸 눈·코·입 안쪽**만, **수만 명을 가르도록 학습된 기준**으로 본다. 사람은 머리·윤곽·피부톤·분위기 전체를 본다. 나이 변환은 모델이 보는 바로 그 부분(뼈 비율, 눈매, 피부결)을 바꾼다 |
| 반대로 높게 나와서 속는 경우도 있나? | 있다. 결과가 "평균 얼굴" 로 몰리면 본인 점수도 오르지만 **남과의 점수도 같이 오른다** (ai_lab test: 결과끼리 유사도 0.215 → 0.407). 그래서 점수 하나만 보지 않는다 |
| 다른 측정 도구는? | 목적별로 다르다. 신원은 **검색 순위(Top-1)·margin·TAR@FAR**, 같은 나이 비교(복원·안경)는 **LPIPS·SSIM**, 전체 인상은 **CLIP·DINOv2**, 최종 판단은 **사람 라인업 평가** (6장) |
| 결론 | ArcFace·AdaFace 는 버리지 않는다. **절대값 대신 기준선 대비**로 읽고, 검색 지표와 사람 평가를 같이 붙인다 |

## 1. 이미지 유사도는 "무엇이 같은가" 에 따라 종류가 다르다

"두 사진이 비슷하다" 는 말에는 여러 뜻이 섞여 있다. 지표마다 보는 층이 다르다.

| 층 | 대표 지표 | 무엇을 비교하나 | 머리를 바꾸면 | 나이를 바꾸면 |
|---|---|---|---|---|
| ① 픽셀 | MSE, PSNR | 같은 위치 픽셀 색 차이 | 크게 떨어짐 | 크게 떨어짐 |
| ② 구조 | SSIM | 작은 창 안의 밝기·대비·무늬 | 떨어짐 | 떨어짐 |
| ③ 지각(사람 눈 흉내) | LPIPS, DISTS | 이미지 분류망 중간 특징 차이. 사람의 "비슷해 보인다" 판단에 맞춰 보정됨 | 떨어짐 | 떨어짐 |
| ④ 의미 | CLIP, DINOv2 코사인 | "무엇이 찍혔나"(성인 남성, 단발, 안경…) | 조금 떨어짐 | 조금 떨어짐 |
| ⑤ **신원** | **ArcFace, AdaFace** 코사인 | **누구인가** | 거의 그대로 (그렇게 학습됨) | **떨어짐** (얼굴 자체가 바뀜) |

- ①~③ 은 **같은 사진의 전후**(복원, 안경 합성)를 비교할 때 쓰는 지표다. 아이 → 성인처럼 얼굴이 원래 달라져야 하는 경우에는 쓸 수 없다.
- ⑤ 는 "머리·조명·표정·배경이 달라도 같은 사람이면 같게" 나오도록 만든 지표다. 그래서 나이 변환 평가에 쓴다. 대신 **"사람이 보기에 비슷한가"** 를 재는 지표가 아니다.

## 2. ArcFace 는 어떻게 숫자를 만드나

### 2-1. 처리 흐름 (이 저장소 코드)

```
사진 → RetinaFace 로 얼굴·5점(두 눈, 코, 입 양끝) 찾기
     → 5점을 고정 위치로 맞춰 112×112 로 자르기          src/align.py  arcface_align
     → ResNet50 (w600k_r50.onnx) → 숫자 512개(임베딩)     src/stages/evaluate.py  ArcFaceEvaluator
     → 두 임베딩의 코사인 유사도 (-1 ~ 1)                 src/stages/evaluate.py  cosine
```

- 112×112 는 이마 위·턱 아래·귀 바깥이 거의 잘린 크기다. **머리 모양, 얼굴 윤곽 바깥, 배경은 처음부터 거의 안 본다.**
- 코사인 유사도는 512차원 공간에서 두 화살표 사이 각도의 cos 이다. 같은 방향이면 1, 직각이면 0.

### 2-2. 학습 원리: "각도에 여유(margin)를 주는 분류"

ArcFace (Deng 외, CVPR 2019) 는 수십만 명의 얼굴로 "이 사진은 몇 번 사람인가" 를 맞히게 학습한다. 서버가 쓰는 `w600k_r50` 은 insightface buffalo_l 의 ResNet50 으로, WebFace600K 로 학습됐다.

일반 분류와 다른 점은 **정답 사람과의 각도 θ 에 여유 m 을 더해서** 일부러 어렵게 만든다는 것이다.

```
일반 softmax:   점수 = s · cos(θ)
ArcFace:        정답 칸만  s · cos(θ + m)     (보통 m = 0.5 라디안, s = 64)
```

- 정답 사람의 대표 방향과 **각도가 m 만큼 더 가까워야** 맞힌 것으로 쳐 준다.
- 결과: 같은 사람 사진들은 한 방향으로 좁게 모이고, **다른 사람들은 서로 거의 직각**(코사인 ≈ 0)으로 흩어진다.

이 학습 방식에서 나오는 성질이 사람 체감과 어긋나는 원인이다.

| 성질 | 왜 생기나 | 체감과의 차이 |
|---|---|---|
| 남남이 0 근처 | 수십만 명을 서로 직각으로 떼어 놓도록 학습 | 사람은 "남인데 좀 닮았다" 를 느끼지만, 모델은 닮은 남도 0.1~0.2 정도로 낮게 준다. **점수 눈금이 0~1 에 고르게 펴져 있지 않다** |
| 구분에 쓸모 있는 단서만 남김 | 수십만 명을 가르는 데 도움이 되는 정보만 512개에 담는다 | 사람이 "분위기" 로 느끼는 머리·피부톤·표정은 **일부러 지운 정보**다 |
| 미세한 안쪽 구조에 민감 | 눈 사이 거리, 눈꺼풀 모양, 코·입 비율, 눈 주변 질감 등이 사람을 가르는 핵심 단서 | 사람에게 작아 보이는 눈매 변화가 점수를 크게 깎는다 |
| 학습 데이터에 없는 경우에 약함 | 학습 사진은 대부분 성인, 실제 사진 | **아이 얼굴, GAN 이 만든 얼굴**은 익숙하지 않은 입력이다 |

### 2-3. AdaFace 는 무엇이 다른가

AdaFace (Kim 외, CVPR 2022) 도 같은 "여유를 주는 분류" 방식이다. 다른 점은 **사진 품질에 따라 여유를 바꾼다**는 것이다.

- 임베딩의 길이(norm)를 사진 품질의 대리값으로 쓴다. 선명한 사진은 길고, 흐리거나 작은 사진은 짧다.
- 선명한 사진은 **어려운 사진에 집중**해서 배우고, 흐린 사진은 **억지로 맞추지 않게**(쉬운 사진 위주로) 배운다.
- 그래서 흐리고 작은 얼굴(CCTV, 오래된 사진)에서 ArcFace 보다 덜 흔들린다.
- ai_lab 이 쓰는 것은 IR-101, WebFace12M 학습판이다 (`src/stages/evaluate.py` `AdaFaceEvaluator`). 서버에는 AdaFace 코드·가중치가 없어 ArcFace 만 쓴다 (docs/[02]).

**둘 다 "누구인가" 를 가르는 망**이라 1장의 성질은 같다. AdaFace 가 사람 체감에 더 가깝다는 뜻은 아니다. ai_lab 에서 AdaFace 를 "가장 믿을 만하다" 고 한 이유는 학습에도 체크포인트 고르기에도 안 써서 **모델이 이 채점자를 속였을 가능성이 없기 때문**이다 (ai_lab docs/[10] 1-3).

## 3. 점수 눈금 읽는 법: 절대값이 아니라 기준선과 비교

코사인 값은 그 자체로 "몇 % 닮음" 이 아니다. 같은 망으로 잰 **기준선**과 나란히 놓아야 뜻이 생긴다.

ArcFace (w600k_r50), ai_lab 실제 사진 기준 (ai_lab docs/[10] 2-D, `experiments/best11_compare/meta.json`):

```
 0.0        0.046            0.278                    0.443                1.0
  |----------●-----------------|-------------------------●--------------------|
         남남 평균        "같은 사람" 판정선          본인끼리 평균
                      (남을 본인으로 볼 확률 1%)      (나이 다른 실제 사진)
```

같은 눈금 위에 나이 변환 결과를 놓으면:

| 비교 | ArcFace | 출처 |
|---|---|---|
| 어릴 때 사진 그대로 ↔ 본인 현재 사진 (변환 없음) | 0.346 | ai_lab test 77건 |
| 원본 SAM 결과 ↔ 본인 현재 사진 | 0.198 | 같음 |
| 최종 모델 결과 ↔ 본인 현재 사진 | 0.256 | 같음 |
| 서버 나이 변환 결과 ↔ 입력 사진 (30/50세) | 0.449 / 0.469 | 이 저장소 docs/[00] 5장, 성인 사진 1장 |

읽는 법:
- 최종 모델 0.256 은 남남 평균(0.046)보다 **다섯 배 이상 높다**. "모르는 사람" 수준이 아니다.
- 다만 판정선 0.278 보다는 아래라서, 평균적으로는 "확실히 같은 사람" 으로 판정되지 않는다 (ai_lab docs/[10] 2-D).
- 서버 화면의 0.45 는 **입력 사진 대비** 점수다. 비교 대상이 다르므로 ai_lab 의 0.256(실제 현재 사진 대비)과 직접 비교하지 않는다.

## 4. 사람 체감과 어긋나는 이유 (이 프로젝트에서 실제로 본 사례)

### 4-1. 낮게 나오는데 사람 눈엔 같은 사람

| 사례 | 잰 값 | 사람 눈 | 왜 어긋나나 |
|---|---|---|---|
| **나이 변환** | 입력 대비 0.449 / 0.469 (30/50세, docs/[00]) | 같은 사람이 나이 든 모습 | 나이 변환은 뼈 비율·눈꺼풀·주름·피부결을 바꾼다. 이것이 ArcFace 가 사람을 가르는 핵심 단서다. **실제 사진끼리도 나이가 다르면 평균 0.443** 이므로, 0.45 는 "같은 사람의 다른 나이" 로서 정상 범위다 |
| **CodeFormer 복원** | 원본 대비 w=0: 0.463, w=0.5: 0.731, w=1: 0.869 (docs/[00] 4장) | w=0 이 가장 선명하고 보기 좋다 | 복원망이 "깨끗한 얼굴" 을 새로 그리면서 눈매·피부 미세 구조를 자기 식으로 바꾼다. 사람은 선명해졌다고 느끼고, ArcFace 는 단서가 바뀌었다고 본다 |
| **복원 뒤 나이 변환** | 원본 대비 30/50세: 원본으로 0.461/0.361 → 복원 얼굴로 0.298/0.197 (docs/[01] 10-26) | 복원 얼굴이 더 자연스러워 보일 수 있다 | 복원이 깎은 신원 위에 나이 변환이 또 깎는다. 깎인 것이 쌓인다 |
| **뿔테 안경** | 안경 전 대비 얇은 테 0.925/0.912, 뿔테 0.860/0.847 (docs/[00]) | 둘 다 당연히 같은 사람 | 112×112 안에서 눈 주변이 가장 중요한 영역인데 굵은 테가 그 부분을 덮는다. 바뀐 픽셀 비율도 7.8~7.9% → 9.2~9.3% 로 늘었다 |
| **머리 스타일** | 잔머리 보완 전후 0.833 → 0.722 등 (ai_lab docs/[22], 이 저장소 docs/[06]) | 머리만 바뀐 같은 사람 | 이마·눈썹을 새로 그리면서 112×112 위쪽이 바뀐다. 머리 자체는 거의 안 보지만 이마·눈썹은 본다 |

공통점: **사람은 "전체 인상" 과 "맥락"(같은 사진에서 나왔다는 사실)으로 판단**하고, **ArcFace 는 맥락 없이 눈·코·입 안쪽의 세부만**으로 판단한다. 사람은 "저 사진을 바꾼 것" 이라는 걸 알기 때문에 더 관대하다.

### 4-2. 높게 나오는데 실제로는 구분력이 떨어진 경우

반대 방향의 괴리도 있다. ai_lab test (ai_lab docs/[10] 3·4장, ArcFace):

| | 원본 SAM | 최종 모델 |
|---|---|---|
| 본인 유사도 (sim) | 0.198 | **0.256** (올랐다) |
| 77명 중 1등으로 본인 찾기 (Top-1) | 46.8% | **31.2%** (떨어졌다) |
| 서로 다른 사람의 결과끼리 유사도 (8명) | 0.215 | **0.407** (두 배) |

결과가 "성인 평균 얼굴" 쪽으로 몰려서 **누구와 비교해도 조금씩 더 닮게** 나왔다. 본인 점수만 보면 "개선", 여러 명 중에서 찾기로 보면 "후퇴" 다. 사람이 결과 여러 장을 나란히 보면 "다 비슷하게 생겼다" 고 느낄 상황이다.

→ **점수 하나는 위로도 아래로도 사람 체감과 어긋난다.** 그래서 지표를 여러 개 같이 본다.

## 5. 설득용 글 (보고서·발표에 그대로 쓸 수 있는 문단)

> **ArcFace 점수가 낮아 보이는 이유**
>
> ArcFace·AdaFace 는 "두 사진이 얼마나 비슷해 보이는가" 가 아니라 "수십만 명 중에서 같은 사람으로 가려낼 수 있는가" 를 재는 도구입니다. 이 모델들은 다른 사람끼리는 점수가 거의 0 이 되도록 일부러 떼어 놓도록 학습되었기 때문에, 점수가 0~1 사이에 고르게 퍼지지 않습니다. 실제 사진으로 재 보면 모르는 사람끼리는 평균 0.046, 같은 사람이라도 나이가 다른 사진끼리는 평균 0.443 이 나옵니다. 따라서 0.4 대 점수는 "40% 닮았다" 가 아니라 **"같은 사람의 다른 나이 사진과 비슷한 수준"** 입니다.
>
> 또한 이 모델들은 112×112 로 잘라낸 눈·코·입 안쪽만 봅니다. 사람이 같은 사람이라고 느끼는 머리 모양, 얼굴 윤곽, 피부톤, 분위기는 모델이 일부러 무시하도록 학습된 정보입니다. 반대로 나이 변환은 모델이 가장 중요하게 보는 눈매·뼈 비율·피부결을 바꾸는 작업이므로, 잘 된 나이 변환이라도 점수는 내려가는 것이 정상입니다.
>
> 그래서 우리는 점수의 절대값이 아니라 **같은 조건의 기준선과의 차이**로 평가합니다. 최종 모델은 원본 SAM 대비 test 에서 ArcFace +0.052, AdaFace +0.061 (p<1e-9, 77건 중 79% 개선) 높았고, 이는 서로 다른 두 평가 망에서 같은 방향으로 확인된 결과입니다. 동시에 점수가 높게 나와도 결과가 평균 얼굴로 몰리는 경우가 있어, 여러 후보 중 본인을 찾는 검색 순위(Top-1)도 함께 보고합니다.

(+0.052 / +0.061 / 79% 는 ai_lab docs/[02]·[05] 의 test 값이다. 숫자를 바꿔 쓸 때는 dev/test 와 인원 수를 같이 적는다.)

## 6. 다른 측정 도구

목적에 따라 고른다. **신원 판단은 여전히 얼굴 인식 망이 맡고, 나머지는 보완용**이다.

### 6-1. 목적별 지표 표

| 목적 | 지표 | 장점 | 한계 / 이 프로젝트에 쓸 곳 |
|---|---|---|---|
| **검색이 되나** | Top-1·Top-5·평균 순위 | 실종아동 찾기 시나리오와 가장 가깝다. 평균 얼굴로 몰리는 문제를 잡는다 | 후보 수에 따라 값이 바뀐다. ai_lab `eval_kinship.py` 에 있음 |
| **남과 구분되나** | margin (본인 − 남), 결과끼리 유사도 | sim 이 거짓으로 오르는 것을 잡는다 | ai_lab 에서 8명만 계산함. 전체는 아직 (ai_lab docs/[10] 2-C) |
| **같은 사람 판정** | TAR@FAR (남을 본인으로 볼 확률 1%·0.1% 고정 시 본인 맞힘 비율) | 얼굴 인식 분야 표준. 점수 눈금 문제를 없앤다 | 아직 계획 단계 (ai_lab docs/[10] 2-D) |
| **다른 얼굴 인식 망으로 교차 확인** | MagFace, ElasticFace, TransFace, FaceNet 등 | 망 하나의 버릇에 결론이 휘둘리지 않는다. MagFace 는 임베딩 길이로 얼굴 품질도 준다 | 학습 손실용(IR-SE50)과 겹치면 안 된다 (AGENTS.md). ai_lab 에 MagFace 자리만 있음 (`stub`) |
| **같은 나이 전후가 비슷해 보이나** | LPIPS, DISTS, SSIM | 사람 눈 판단과 잘 맞는다 (LPIPS 는 사람 판단 데이터로 보정됨) | **복원·안경처럼 얼굴이 원래 같아야 하는 단계에만**. 나이 변환에는 쓰면 안 된다 |
| **바뀌면 안 되는 곳이 그대로인가** | 마스크 영역 픽셀 차이 | 단순하고 확실하다 | 이미 안경에서 `changed_ratio` 로 쓴다 (이마 위·입 아래 0 확인) |
| **전체 인상이 비슷한가** | CLIP, DINOv2 임베딩 코사인 | 머리·분위기·윤곽까지 본다. 사람 체감에 더 가깝다 | **신원 지표가 아니다.** 같은 머리 모양의 남도 높게 나온다. 참고용 |
| **사진이 자연스러운가** | FID·KID (결과 묶음 ↔ 실제 사진 묶음 분포), 무참조 품질(MUSIQ, CLIP-IQA), 얼굴 품질(SER-FIQ, CR-FIQA) | GAN 티, 흐림을 숫자로 잡는다 | FID 는 수천 장이 있어야 안정적. 사람 1명 단위 판단 불가 |
| **목표 나이가 맞나** | 나이 추정기 오차 (MiVOLO 등) | 나이를 덜 바꿔서 신원 점수만 올리는 꼼수를 잡는다 | 나이 추정기도 아이·노인에서 오차가 크다. 평가용은 학습용과 다른 망 |

### 6-2. 사람 평가 (가장 설득력 있음)

숫자 지표가 사람 체감과 어긋난다면, 결국 **사람에게 직접 물어보는 것**이 최종 근거다. 실종아동 검색 목적에 맞는 방식:

| 방식 | 어떻게 | 무엇을 아나 |
|---|---|---|
| **라인업(줄 세우기)** | 결과 1장 + 실제 현재 사진 5~10장(본인 1 + 남) 을 보여 주고 "누구인가" 고르기 | 사람 기준 Top-1. ArcFace Top-1 과 나란히 놓으면 "모델 점수와 사람 판단이 얼마나 맞나" 를 숫자로 보여 줄 수 있다 |
| **둘 중 고르기 (2AFC)** | 원본 SAM 결과 vs 최종 모델 결과, "어느 쪽이 실제 사진과 더 닮았나" | 모델 간 비교. 눈금 문제가 없다 |
| **점수 매기기 (MOS)** | 1~5점 "같은 사람 같은가", "자연스러운가" | 단순하지만 사람마다 기준이 달라 평가자 수가 많아야 한다 |

- 얼굴 사진은 AI Hub 재배포 금지 데이터라, 평가 화면은 내부에서만 띄우고 결과 사진을 밖으로 내보내지 않는다 (AGENTS.md 3장).
- 평가자 수, 문항 수, 사진 선택 방법을 미리 정하고 결과와 함께 적는다.

## 7. 정리

1. ArcFace·AdaFace 는 **"누구인가" 를 가르는 도구**이지 **"비슷해 보이는가" 를 재는 도구가 아니다.**
2. 학습 방식 때문에 남남은 0 근처, 나이 다른 본인은 0.4 대가 정상이다. **0.4 = 40% 가 아니다.**
3. 112×112 안쪽만 보므로 머리·윤곽·분위기는 반영되지 않고, 나이 변환·복원·안경이 건드리는 눈매·피부결에는 민감하다.
4. 점수는 체감보다 낮게도(나이·복원·안경), 높게도(평균 얼굴) 어긋난다. 그래서 **기준선 대비 차이 + 검색 순위 + 사람 평가** 를 같이 본다.
5. 같은 나이 전후 비교(복원·안경)에는 LPIPS 같은 지각 지표가 사람 체감에 더 가깝다. 나이 변환에는 쓰지 않는다.
