# [03] 가중치 교체 가이드

> 2026-10-20 작성. 현재 서버 코드가 읽는 위치와 파일 형식을 기준으로 정리했다.
> 가장 자주 바꿀 파일은 나이 인코더 `weights/sam/best_encoder.pt`다.

기본 순서는 **서버 종료 → 기존 파일 백업 → 새 파일을 같은 위치에 복사 → 점검 → 서버 재실행 → 새 변환 요청**이다.

## 1. 어떤 파일을 바꾸는가

아래 경로는 모두 서버 저장소 폴더 기준이다. **기존 파일명과 위치를 유지해서 교체하면 설정을 바꿀 필요가 없다.**

| 바꿀 대상 | 서버가 읽는 파일 | 확인할 점 |
|---|---|---|
| 튜닝한 나이 인코더 | `weights/sam/best_encoder.pt` | SAM의 나이 인코더 전체 가중치. 파일 안에 `encoder` 항목이 있어야 한다. 아래 2장 참고 |
| SAM 본체 | `weights/sam/sam_ffhq_aging.pt` | 나이 인코더·재구성 인코더·디코더가 들어 있는 SAM 체크포인트. 현재 코드가 읽는 `opts`, `state_dict`, `latent_avg` 구조와 맞아야 한다 |
| 성별 보정 | `weights/kin/gender_dir.pt` | 현재 SAM·인코더 조합에 맞는 성별 방향과 판정기. 아래 3장 참고 |
| 성별 보정에 쓰는 얼굴 인식 망 | `weights/ir_se50/model_ir_se50.pth` | IR-SE50과 같은 구조여야 한다. 평가용 ArcFace·AdaFace 파일을 대신 넣지 않는다 |
| 얼굴 검출 | `weights/facexlib/detection_Resnet50_Final.pth` | RetinaFace ResNet50용 가중치여야 한다 |
| 나이 변환 신원 점수 | `weights/arcface/w600k_r50.onnx` | insightface 형식 ArcFace ONNX (입력 112x112 RGB, 출력 512차원). 바꾸면 `extra.identity` 점수 기준이 달라지므로 이전 점수와 비교하지 않는다 |
| 흑백 사진 컬러화 | `weights/codeformer/codeformer_colorization.pth` | 현재 CodeFormer 구조와 맞는 컬러화 체크포인트. 코드가 `params_ema` 항목을 읽는다 |
| 머리 스타일·분할 | `third_party/HairFastGAN/pretrained_models/` | 여러 모델이 함께 쓰인다. 파일별 위치는 [구축 가이드](./[02]_구축_가이드.md) 1장 참고. 서로 맞는 버전으로 준비한다 |

파일 확장자가 `.pt` 또는 `.pth`로 같아도 서로 다른 모델의 가중치는 교환할 수 없다. 새 모델 구조가 필요한 변경은 `ai_lab`에서 실험·확인한 뒤 관련 코드와 가중치를 함께 가져온다. 서버에서 `src/`를 임의로 바꾸어 맞추지 않는다.

## 2. 나이 인코더를 교체하는 순서

### 2-1. 서버를 완전히 종료한다

서버를 켠 창에서 `Ctrl+C`를 누른다. 일괄 작업 종료를 묻는 창이 나오면 종료한다. 이 저장소를 쓰는 서버가 여러 개 켜져 있으면 모두 종료한다.

모델이 메모리에 남을 수 있으므로 교체 뒤에는 서버를 새로 실행한다. 실행 중인 파일에 덮어쓰지 않는다.

### 2-2. 새 파일의 종류를 확인한다

현재 설정은 다음과 같다.

```yaml
aging:
  adapter: null
  encoder_lora: null
  encoder_full: weights/sam/best_encoder.pt
```

서버는 `best_encoder.pt`를 열어 `checkpoint["encoder"]`를 나이 인코더에 넣는다. 필요한 파일의 모양은 다음과 같다.

```python
{
    "encoder": 나이_인코더의_state_dict,  # 필수: 현재 SAM의 4채널 입력 인코더와 같은 구조
    "step": 학습_단계,                  # 선택: 없어도 불러올 수 있음
    "metrics": 학습_기록,               # 선택: 없어도 불러올 수 있음
}
```

`best_encoder-step-300.pt`처럼 받은 이름은 달라도 된다. **파일 안의 형식이 맞아야 하며, 서버에 둘 때 이름을 `best_encoder.pt`로 맞춘다.** LoRA 파일이나 인코더의 `state_dict`만 바로 저장한 파일은 이름만 바꿔 넣을 수 없다. 학습한 SAM 본체가 현재 서버의 SAM 본체와 같은 기준인지도 `ai_lab`에서 확인한다.

### 2-3. 기존 파일을 백업하고 새 파일을 복사한다

서버를 종료한 뒤 PowerShell에서 실행한다. 다른 PC라면 저장소 경로를 바꾸고, `새_나이_인코더.pt`는 실제 받은 파일명으로 바꾼다.

```powershell
Set-Location 'C:\Users\rbwns\Desktop\FIndUs\findus_ai_server_final'

$newWeight = Join-Path $env:USERPROFILE 'Downloads\새_나이_인코더.pt'
$activeWeight = Join-Path (Get-Location).Path 'weights\sam\best_encoder.pt'
$backupDir = Join-Path (Get-Location).Path ('weights\_backup\' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff'))

if (-not (Test-Path -LiteralPath $newWeight -PathType Leaf)) { throw '새 가중치 파일이 없습니다. 경로를 확인하세요.' }
New-Item -ItemType Directory -Path $backupDir -ErrorAction Stop | Out-Null
Copy-Item -LiteralPath $activeWeight -Destination (Join-Path $backupDir 'best_encoder.pt') -ErrorAction Stop
Write-Output ('백업 위치: ' + $backupDir)
Copy-Item -LiteralPath $newWeight -Destination $activeWeight -Force -ErrorAction Stop

Get-FileHash -LiteralPath $newWeight, $activeWeight -Algorithm SHA256
```

마지막에 나온 두 SHA-256 값이 같으면 받은 파일과 서버에 복사한 파일의 내용이 같다. 제공자가 해시를 함께 줬다면 그 값과도 비교한다. 백업 파일은 `weights/_backup/` 아래에 남는다.

### 2-4. 형식과 준비 상태를 확인한다

같은 PowerShell 창에서 실행한다.

```powershell
.\.venv\Scripts\python.exe -c "import torch; c=torch.load('weights/sam/best_encoder.pt', map_location='cpu', weights_only=True); assert isinstance(c, dict) and 'encoder' in c, 'encoder 항목이 없습니다'; print('encoder 항목 확인:', len(c['encoder'])); print('step:', c.get('step'))"
if ($LASTEXITCODE -ne 0) { throw '새 인코더를 읽지 못했습니다. 오류 내용을 확인하세요.' }

.\.venv\Scripts\python.exe scripts/check_setup.py
```

첫 명령은 CPU에서 파일을 읽고 `encoder` 항목이 있는지 확인한다. 인코더의 모든 키·크기가 맞는지와 실제 출력은 다음 단계의 변환 요청에서 확인한다.

`check_setup.py`의 파일 크기는 **처음 배포한 가중치 기준**이다. 그 크기에서 10% 넘게 달라지면 `크기 다름`이 나온다. 새 체크포인트의 저장 형식이나 부가 기록 때문에 크기가 달라질 수도 있으므로, 이 메시지만으로 다운로드 실패나 호환 여부를 단정하지 않는다. 원본 파일·해시·형식과 실제 로드 결과를 함께 확인한다.

### 2-5. 서버를 켜고 새 변환을 요청한다

```powershell
.\start_server.bat
```

브라우저에서 `http://127.0.0.1:8000/`을 연다. 같은 사진·나이·성별·성별 보정 세기로 **새 변환 요청**을 보내 이전 결과와 비교한다. `/health`가 정상이어도 새 가중치로 실제 변환이 성공하는지까지 확인해야 한다.

이미 만든 `outputs/`의 결과는 교체 뒤에도 바뀌지 않는다. 새 요청이 만든 새 `result_id`의 결과를 확인한다. 머리 변환도 쓴다면 나이 변환 결과에 머리를 적용해 보고, 다시 나이 변환을 요청해 모델 전환까지 확인한다. GPU가 6GB이므로 `ai_lab` 서버와 동시에 켜지 않는다.

## 3. 성별 보정 파일도 교체할 때

`weights/kin/gender_dir.pt`도 **서버 종료 → 기존 파일 백업 → 같은 경로에 새 파일 복사 → 서버 재실행 → 새 변환** 순서로 바꾼다. 2-3의 `$newWeight`는 받은 성별 보정 파일로, `$activeWeight`는 `weights\kin\gender_dir.pt`로 바꾼다. 백업·복구 명령의 파일명도 `gender_dir.pt`로 맞춘다.

현재 로더가 읽는 항목은 다음과 같다.

| 항목 | 역할 |
|---|---|
| `dir` | 성별 방향 텐서. 현재 코드는 18층 × 512차원 latent에 적용한다 |
| `latent_avg` | 해당 SAM의 latent 기준값 |
| `bounds` | `M`, `F` 보정 경계값 |
| `head` | IR-SE50 임베딩 위의 성별 판정기. 현재 그림 보고 고치기 단계가 사용한다 |

`head`가 없으면 코드가 방향 보정만 수행하고 그림 보고 고치기는 건너뛴다. 현재 구성과 같은 동작을 유지하려면 판정기까지 포함한 파일을 받는다.

새 나이 인코더나 SAM 본체가 기존 `gender_dir.pt`와 맞는지는 별도로 확인해야 한다. **새 인코더를 넣었다고 성별 보정 파일이 자동으로 다시 만들어지지는 않는다.** `ai_lab`에서 해당 조합을 확인한 파일을 받아 사용한다. 두 파일을 함께 바꿨다면 문제가 생겼을 때도 함께 이전 조합으로 되돌린다.

## 4. 문제가 생겼을 때 되돌리기

먼저 서버를 종료한다. 2-3에서 사용한 **같은 PowerShell 창**이라면 다음 명령으로 기존 인코더를 복구한다.

```powershell
Copy-Item -LiteralPath (Join-Path $backupDir 'best_encoder.pt') -Destination $activeWeight -Force -ErrorAction Stop
Get-FileHash -LiteralPath (Join-Path $backupDir 'best_encoder.pt'), $activeWeight -Algorithm SHA256
.\start_server.bat
```

PowerShell 창을 닫았다면 `weights/_backup/`에서 교체 전 백업을 골라 `weights/sam/best_encoder.pt`에 복사한 뒤 실행한다. 여러 파일을 바꿨다면 각각의 백업을 같은 조합으로 복구한다.

| 오류·증상 | 확인할 것 |
|---|---|
| `FileNotFoundError` | 설정의 경로, 파일명, 확장자, 압축이 한 폴더 더 안쪽에 풀렸는지 확인 |
| `KeyError: encoder` | SAM 나이 인코더 전체 체크포인트인지 확인. LoRA나 다른 형식이면 `ai_lab`에서 맞는 형식으로 준비 |
| `Missing key`, `Unexpected key`, `size mismatch` | 모델 구조·키·텐서 크기가 다름. 이전 파일로 복구하고 학습 쪽 조합 확인 |
| `weights_only` 로드 오류 | 현재 로더가 읽을 수 있는 저장 형식인지 확인. `ai_lab`에서 호환 형식으로 다시 저장 |
| `CUDA out of memory` | 다른 GPU 서버 종료, 변경한 모델이 현재 구조·메모리 조건과 맞는지 확인 |
| 화면에 예전 결과가 보임 | 서버를 재실행했는지, 새 요청의 결과인지 확인 |

## 5. 교체 기록과 동기화 주의점

- 받은 파일명·출처·학습 실험 이름·SHA-256·백업 위치를 남긴다. `docs/[01]_진행_과정.md` 맨 아래 변경 기록에 교체 파일과 실제 확인 결과를 적는다. 품질 점수를 기록한다면 `ai_lab`의 출처와 dev/test 구분을 함께 적는다.
- `configs/final.yaml`은 서버 전용 조합이다. 파일 이름을 그대로 유지하는 교체에는 수정이 필요 없으며, `ai_lab`의 설정 전체를 덮어쓰지 않는다. 현재 `adapter: null`, `encoder_lora: null`도 그대로 둔다.
- `scripts/sync_assets.py`는 `ai_lab`의 `sam_encoder_full_ft.pt`를 서버의 `best_encoder.pt`로 복사한다. 동기화를 다시 실행하면 조건에 따라 방금 교체한 파일이 덮어써질 수 있으므로, 먼저 교체 파일과 백업을 확인한다.
- 가중치와 백업은 git에서 제외되는 `weights/` 또는 해당 모델 폴더 안에 보관한다. 얼굴 사진·결과는 `data/`, `outputs/`에 보관하며 커밋하지 않는다.
