## 2. 기존 모델로 되는가

| 필요한 것 | 기존에 있는 것 | 새로 |
|---|---|---|
| 얼굴 찾기·정면 정렬 | RetinaFace + `src/align.py` `ffhq_align` (올린 사진은 `HairPost.align`) | 없음 |
| 두 눈 위치·눈 거리 | BiSeNet 눈(4·5) → `hair_fit.measure` 의 `eye`, `D` | 기울기 계산 몇 줄 |
| 안경 폭 | `measure` 의 `temple` (눈 높이 얼굴 폭) | 없음 |
| 다리를 머리카락 밑으로 | BiSeNet 머리(17)·귀(7·8) | 없음 |
| 테 그림자 | BiSeNet 피부(1) | 몇 줄 |
| 이미 안경 쓴 얼굴 | BiSeNet 안경(6) | 없음 |
| 안경 전후 신원 점수 | ArcFace (`extra.identity` 와 같은 방식) | 없음 |
| **안경 그림** | 없음 | **사진 2장** |

BiSeNet 은 `src/hair_color.py` 의 `HairMask("cpu")` 로 CPU 에서 돈다 (머리 참조 썸네일에서 이미 쓴다). 그래서 안경 단계는 나이·머리 모델을 GPU 에서 내리지 않는다.

## 4. 합성 순서 (`src/glasses.py`)

1. `parse = HairMask("cpu").parse(img)`, `m = hair_fit.measure(parse)` → 눈 중심·눈 거리·얼굴 폭. 눈을 못 찾으면 400.
2. 안경 사진의 두 렌즈 중심이 두 눈에 오도록 크기·각도를 맞춘다 (`cv2.warpAffine`). 사용자 `scale` 을 곱한다.
3. 피부(1) 영역에만 테 그림자.
4. 안경을 얹는다. 머리카락(17)이 덮는 곳은 다리를 지운다.
5. **원본 유지 규칙**: 안경 알파 + 그림자 마스크 밖의 픽셀은 입력을 그대로 복사한다 (계산 오차로도 바뀌지 않게). 렌즈 안쪽은 원본 눈 위에 아주 옅은 반사만 얹는다.
6. 반환: 결과 이미지, `info` (`style`, `scale`, `had_glasses`, `changed_ratio` = 바뀐 픽셀 비율).

## 8. 수정 계획: 얼굴 크기·귀 위치 반영 (2026-10-26 검토, 구현 전)

### 8-1. 지금 방식과 한계

| | 지금 (`src/glasses.py`) | 한계 |
|---|---|---|
| 크기 | 두 렌즈 중심 거리 = 두 눈 거리. 테 폭이 얼굴 폭 × 1.08 을 넘으면 줄임 | 눈 사이가 넓거나 좁은 얼굴에서 테가 얼굴보다 크거나 작아 보일 수 있음 |
| 높이 | 렌즈 중심 = 눈 중심 + 눈 거리의 4% 아래 | 귀 높이를 안 봐서 다리가 걸칠 곳과 상관없이 놓인다 |
| 기울기 | 두 눈을 이은 선 | 눈 분할이 조금 틀리면 그대로 기운다 |
| 다리 | 그리지 않음 (테 끝만, 머리카락이 덮으면 지움) | 얼굴보다 귀가 바깥에 있으면 테 끝과 귀 사이가 비어 보일 수 있음 |

### 8-2. 해 본 측정 (이 PC, BiSeNet, 사진 3장, dev/test 아님)

| 사진 | 눈 거리 | 눈 높이 얼굴 폭 (x) | 귀 (윗끝 y, x 범위) | 지금 뿔테 x 범위 | 눈 y |
|---|---|---|---|---|---|
| kid.jpg → 30세 | 249 | 254~783 | 둘 다: 윗끝 440, 164~261 / 776~897 | 251~783 | 487 |
| kid.jpg → 50세 | 249 | 254~781 | 둘 다: 윗끝 436 | 251~783 | 487 |
| iu.png (여자아이, 정렬만) | 256 | 222~769 | **한쪽만** (다른 쪽은 머리카락에 가림): 윗끝 438, 754~841 | 226~772 | 483 |

- 귀(라벨 7·8)는 지금 쓰는 얼굴 분할에서 이미 나온다. 새 모델이 필요 없다.
- 지금 테 끝은 얼굴 가장자리와 거의 같다 (차이 3px 이내). 정면에서는 이게 자연스럽다.
- 귀 윗끝은 눈보다 눈 거리의 약 18% 위 (436~440 vs 483~487). 실제 안경의 경첩 높이와 비슷해서 **높이 기준으로 쓸 수 있다.**
- 머리카락이 귀를 덮는 경우가 있다 (iu.png). **귀 한쪽 또는 둘 다 없을 때의 대체 방법이 꼭 필요하다.**

### 8-3. 바꿀 방법

1. **크기는 얼굴 폭 기준**: 테 앞면 폭 = 경첩 높이의 얼굴 폭 × 1.00~1.04 (뿔테는 조금 넓게, 얇은 테는 딱 맞게. 프리셋 값). 그다음 눈동자가 렌즈 가운데 ±15% 안에 들어오는지 확인하고, 벗어나면 눈 거리 기준 크기와 섞어 맞춘다.
2. **높이는 귀 기준**: 에셋에 경첩 두 점(`hinges`)을 새로 적어 두고, 경첩 높이 = 귀 윗끝 + 눈 거리 × 약간 (값은 사진으로 맞춤). 단 눈동자가 렌즈 높이의 35~60% 안에 오도록 제한한다 (눈을 테가 가리지 않게).
3. **기울기는 눈 + 귀**: 두 귀가 다 보이면 두 귀 윗끝을 이은 선과 두 눈을 이은 선의 각도를 평균. 둘 중 하나가 크게 다르면(분할 오류) 눈 선만 쓴다.
4. **다리 그리기**: 경첩에서 귀 윗뿌리(귀 윤곽의 얼굴 쪽 위 끝)까지 짧은 다리를 테 색으로 그린다. 머리카락이 덮는 곳은 지우고, 귀에 닿는 곳에서 끝낸다. 귀가 얼굴 가장자리 안쪽이면(정면) 다리는 거의 안 보이는 게 맞으므로 그리지 않는다.
5. **귀가 안 보일 때**
   - 한쪽만 보이면: 보이는 귀를 얼굴 가운데 선(두 눈 중간)에 대해 좌우로 뒤집어 쓴다.
   - 둘 다 안 보이면: 지금처럼 얼굴 폭·눈 기준으로만 맞추고 다리는 그리지 않는다.
   - 귀걸이(라벨 9)는 귀로 치지 않는다.
6. **(2단계, 선택) 고개 돌림**: 눈 중간에서 왼쪽·오른쪽 얼굴 끝까지 거리가 많이 다르면 먼 쪽 렌즈를 가로로 조금 줄인다. FFHQ 정렬 결과는 대부분 정면이라 1단계에서는 하지 않는다.

`info` 에 맞춤 근거를 남긴다: `fit` = `ears2` / `ears1_mirror` / `face_only`, `width_ratio`, `pupil_in_lens`(눈동자 위치 %), `arms`(다리를 그렸나).

### 8-4. 반영할 수 있나 (검토)

| 항목 | 판단 | 이유 |
|---|---|---|
| 얼굴 폭 기준 크기 | **가능** | `hair_fit.measure` 의 얼굴 폭을 이미 계산 중. 순서만 바꾸면 된다 |
| 귀 기준 높이·기울기 | **가능** | 귀 라벨이 이미 나온다. 사진 3장 모두 보이는 귀는 윤곽이 깨끗했다 |
| 다리 그리기 | **가능, 손이 좀 감** | 다리는 사진에 없어서 그려야 한다. 테 색·굵기를 에셋에서 가져와 짧은 선으로 그리면 충분 (정면이라 거의 안 보임) |
| 귀 가림 대체 | **가능** | 좌우 뒤집기와 지금 방식으로 대체. 3장 중 1장이 한쪽 가림이라 꼭 넣어야 한다 |
| 고개 돌림 | 보류 | 정렬 결과는 대부분 정면. 필요하면 2단계 |
| GPU·속도 | 영향 없음 | 모두 CPU 라벨 계산. 분할은 이미 한 번 하고 있다 |
